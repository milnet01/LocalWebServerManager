### The cross-cutting finding: a fourth non-`OSError` whole-scan crash

Two lanes with different reproducers landed on the same defect, which is the
strongest signal this format produces. `Path.exists` / `is_symlink` / `is_file`
re-raise `EACCES` and `ENAMETOOLONG` on Python 3.13 — `pathlib` only swallows
`ENOENT/ENOTDIR/EBADF/ELOOP` — and four call sites sit outside any handler while
`scan()` catches only `_BudgetExpired`.

Both triggers were reproduced a second time, independently, before being
written down:

- `chmod 000` on any candidate directory → **20 healthy projects returned 0**.
  Needs no attacker.
- A 3000-character hop token in a `start.sh` → `OSError [Errno 36]`. One line,
  attacker-authored.

**This is the fourth distinct shape of the same class** after the `TypeError`,
`KeyError` and `ValueError` the spec gate found. Three loops fixed three
instances; none of them fixed the class. LWSM-1122 fixes it structurally, with
per-candidate containment, which is the only reason to expect a fifth not to
arrive.

### The half that is harder to sit with: 370 green tests proving less than they look

81 mutants were applied to `scanner.py`. **47 went red; 34 did not.** Three
clauses the spec calls load-bearing are correct in the code and protected by
nothing:

- `_BudgetExpired` can be made an `OSError` and all 182 scanner tests stay
  green — while a timed-out scan then reports `timed_out=False`, i.e. claims
  to be complete. LWSM-1007 is about to persist that list.
- The `package.json` dependency-block scope — the spec review's single
  highest-value finding — can be undone silently.
- Rule 1's execute-bit precondition has zero coverage; `scanner.py:943` never
  executes.

**The suite is strong** — 47 reds, all 12 corpus fixtures assert exact
expectations with no "something was detected" anywhere, and every invariant a
reader would guess was "really" tested is tested. The gap is specific, not
general.

### Two things worth carrying forward

**A green-by-construction fixture survived its own correction.** § 12 already
records INV-15's fixture being fixed once for exactly this — `"a"*4092+"port"`
had no separator, so the rule returned early. The replacement reaches
`KEY_IS_PORT` and still makes **zero** calls to the digit scan the invariant
names. Instrumenting the call count, not reading the fixture, is what saw it
(known-issue-026).

**Three sanitiser sweeps in this project have now stopped one call site short.**
`scanner.py:605` is the last unescaped reason (measured at 248 and 635
characters against a 120 cap, carrying live ANSI escapes) and `:467`'s
`PortFinding.source` is sanitised but untested. Both are INV-18 clauses. The
pattern is strong enough that a future sweep should assert the invariant
across all call sites rather than fix the ones it can find.
