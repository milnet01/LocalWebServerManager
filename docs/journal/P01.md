## What was learned

**Checking versions instead of recalling them paid three times in one
phase.** `actions/checkout` was on v7, not the v4 memory offered;
`setup-uv` on v9; and `pytest-qt==4.6.0` — written confidently — has
never existed. Only the resolver caught the last one.

**`--frozen` is not `--locked`.** Measured: with `pyproject.toml` at
`psutil==7.1.0` and `uv.lock` at `7.2.2`, `uv sync --frozen` exits 0
and tests the *old* version. The dependencies standard had credited
`--frozen` with catching exactly that.

**Three defects were invisible to every green signal.** The `lwsm`
console script named a module that did not exist and CI stayed green,
because `compileall` checks files that exist. `get_logger(__name__)`
produced `lwsm.lwsm.<module>` — records still arrived, so nothing
looked wrong. The idempotence guard compared `abspath` against
`resolve()`, so a symlinked state directory wrote every line twice —
and `tmp_path` is never a symlink, so the test that existed to catch
it could not.

**The security pass was the highest-value hour.** Every static scanner
was clean; the real findings came from threat-modelling the *design*.
The app writes its log 0644 and followed a planted symlink (fixed,
with tests); `setuptools` runs code at build time and sits outside the
lockfile entirely (pinned); and six design decisions become
vulnerabilities if implemented as written — folded into FP01 while
they are still cheap to change.
