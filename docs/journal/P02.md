# P02 — Vertical slice (LWSM-1005)

## Close attempted 2026-08-06 — 14 actionable findings folded into FP03

Steps 1–4 were done and green: 5 new modules, 68 tests passing,
`./scripts/local-ci.sh` clean with no SKIPs under
`LWSM_REQUIRE_ALL_TOOLS=1`. Steps 5–6 ran `/audit` plus a three-lane
`/code-quality-review`. **The phase remains 🚧 until FP03 closes.**

### What the tools found: nothing

Every source file came back clean — cppcheck, ruff, bandit, semgrep,
gitleaks and shellcheck. All 173 findings in the sweep were
`contract_doc_drift` against documentation, 168 of them already
allowlisted. This is the **third consecutive phase** where static
analysis found zero real defects and reading found all of them (P01,
FP02, now P02). That is now a pattern worth planning around rather
than a coincidence: the tools earn their place as a regression net,
not as the review.

### What reading found: two CRITICALs, and one of them needed two lanes

**The best finding of the pass could not have come from one lane.**
The data-boundary lane established that `psutil.Error` is neither an
`OSError` nor a `RuntimeError`, and that psutil's own `_pslinux`
raises both bare — so `ports.py`'s `except psutil.Error` has a hole.
The concurrency lane, independently and without seeing that,
established that an exception escaping `QRunnable.run()` is **swallowed
by PySide6**, leaving the in-flight guard set for ever. Neither half
is a defect alone. Together they are: one malformed line in
`/proc/net/tcp` permanently and silently freezes the status display,
at exit 0, with no dialog and no further log line. Reproduced — ten
ticks after the exception issued zero probes.

The partition earned its cost here in exactly the way the skill claims
it can't: the sweep is documented as unable to see defects that live
*between* subsystems, and this one does. It surfaced because both
lanes reported honestly about a boundary rather than certifying it.

**The second CRITICAL is an accessibility failure against the primary
user.** `ProjectRow` is the only focusable widget in the app and
nothing paints a focus ring; grabbing the widget focused and unfocused
produces **identical images**. The user reads with a screen magnifier.

### Three findings that a passing test was actively hiding

- **The glyph is announced.** `setAccessibleName("")` does not remove a
  `QLabel` from the accessibility tree — `QAccessibleDisplay` falls back
  to the label's text. The live interface exposes four children and
  child 0 is named `'●'`. INV-6 passes because it asserts on the
  *row's* name, which is correct; the surface a screen reader actually
  walks was never covered. **A code comment states the opposite as
  fact**, which is worse than an unhandled case: it is a belief that
  was reviewed and was never true.
- **INV-16 passes on wording, not on behaviour.** `stop()` waits for
  `run()` to finish, but the emission is queued *inside* `run()` — so
  it is already posted when the wait returns. The invariant says "no
  task is outstanding" (true) to mean "a snapshot arriving later cannot
  touch a torn-down controller" (false). Zero emissions immediately
  after `stop()`, one after a single event-loop spin.
- **`state_unknown` is 4.46:1** against the window, under the 4.5:1
  `testing.md § T8` requires — in the *default* palette, so it is what
  a first run gets. The contrast test was scheduled with LWSM-1031's
  six palettes; the palette that fails already shipped.

The lesson is consistent across all three: **an invariant is only as
good as the surface its test can reach.** Each was written carefully,
each passes, and each leaves the thing it was protecting uncovered.
Worth carrying into how FP03's red tests are authored — assert against
the observable surface (the AT tree, the rendered image, the arriving
signal), not against the mechanism the code happens to use.

### Deviations from the procedure, recorded rather than hidden

- **No CHANGELOG entry was written.** `/close-phase` § 5a-3 asks for one
  under `### Fixed`, but FP03 has fixed nothing yet — it is a list of
  findings. Writing "Fixed" for unfixed defects would be precisely the
  class of false record this pass exists to catch. The CHANGELOG gets
  its entry when FP03's fixes land, which is what FP02 did.
- **`.audit_cache/` is tracked in git** and the sweep wrote two new
  files there. Left unstaged and unresolved: it is pre-existing (FP02
  committed its own), it is outside P02's scope, and whether a public
  repo should carry its own SARIF reports is the author's call.

### False positives confirmed this close

- **allowlist-006** — 5 `contract_doc_drift` hits inside
  `docs/specs/`, a directory the existing entries did not cover.
  Deliberately scoped to two token classes rather than the directory,
  because the check **is** useful there: four are language/framework
  names in `*Breaks when:*` clauses (a match would evidence the
  defect), and `state_text` is a variable in an illustrative f-string.
- **allowlist-007** — `vulture` on `accent_soft`, `attention` and
  `is_dark` in `theme.py`, plus `pytestmark` in two test files. The
  three fields are the documented outcome of spec § 8's rejected
  alternative, not an oversight; re-verify after LWSM-1031, where they
  *should* gain readers.

**An error of mine, corrected before anything was filed:** the first
`deptry` and `pip-audit` runs were made outside the project's virtual
environment and produced 21 "PySide6 missing from dependency
definitions" findings against a `pyproject.toml` that plainly declares
it. Re-run inside the environment, that collapses to the three
already-known dev-tool entries. Nothing was filed from the bad run.
The same trap as the mutation-testing run during LWSM-1005, in a new
costume: **read the output, not the exit code, and check which
interpreter produced it.**
